Clipboard App — Full Product & Developer Brief
AR Swift Private Limited | Muhammad Adnan | November 7, 2026
Executive Summary
We are building a cross-device clipboard manager for Mac, iPhone, and iPad — a direct competitor to Paste (pasteapp.io), which is the category leader with 10 years on the App Store, 16K+ ratings, and $29.99/year pricing.
The market gap is real. Paste stores everything but organizes nothing automatically. Users with 161 and 125 votes on the public ideas board are asking for export/import and rule-based auto-sorting — features Paste has not built. We will launch with these two unique differentiators built in from day one.
What we are building:
A Mac menu-bar app + iPhone/iPad companion app
Private iCloud sync — no AR Swift servers, zero server cost
Unlimited clipboard history with smart auto-organization
Text transformation tools built into the clipboard
Free tier + paid IAP (monthly, annual, lifetime)
Who it is for: Developers, designers, content creators, and agency teams — professionals who copy and paste constantly and need their clipboard to work smarter.

Technical Blueprint
Important note on technology choice: A clipboard manager on Apple platforms requires deep OS-level access — clipboard monitoring, background execution, keyboard extensions, and iCloud sync via CloudKit. React Native does not support all of these natively. The recommended approach is a hybrid architecture: native Swift/SwiftUI for the platform-critical core, with React Native only for the UI screens if the developer strongly prefers it. However, we strongly recommend going fully native for this app category.

App Architecture (5 Targets)
Mac Menu Bar App — always running in background, monitors NSPasteboard, saves new copies to local SwiftData, syncs to CloudKit, sits in menu bar with ⌘⇧V shortcut
iPhone / iPad App — main clipboard viewer, pinboards, search, settings
iOS Keyboard Extension — a separate app target that reads from CloudKit to show history while typing in any app
iOS Share Extension — another separate target that saves shared items directly to clipboard history
Widget Extension — WidgetKit target for home screen and Dynamic Island display
All five targets share one CloudKit container (the user's private iCloud). No AR Swift server is ever touched.
Key Technical Challenges
These are the hard problems the developer must solve before writing a single UI screen. Address these first in a technical spike (2–3 days of testing before full development begins).
Challenge 1: Mac Accessibility Permission
To monitor the clipboard on Mac, the app needs Accessibility access from the user (System Settings → Privacy & Security → Accessibility). Without it, clipboard monitoring does not work. The app must:
Request this permission on first launch with a clear explanation screen
Handle the case where the user denies it (show a prompt to enable it)
Survive the user revoking permission mid-use
This is a user experience problem as much as a technical one. Paste handles it with an onboarding dialog and an in-app guide (we saw this in the screenshots).
Challenge 2: iOS Has No Background Clipboard Access
Apple does not allow any third-party app to read the clipboard in the background on iOS. This is a hard platform limitation. Every clipboard manager on iOS — including Paste — works around it the same way: a Keyboard Extension.
The solution: Build a custom iOS keyboard extension. When the user wants to access clipboard history on iPhone, they switch to the app's keyboard (hold globe icon → select our keyboard). The extension can read the clipboard when active because the user triggered it. This is not a workaround we invented — it is the only Apple-approved method.
The developer must build this as a separate Xcode target. It has a strict 12 MB memory limit.
Challenge 3: iOS "Paste from Other Apps" Banner
On iOS, every time an app reads the clipboard without the user explicitly pressing Paste, iOS shows a system banner: "[App] pasted from [Other App]." Users find this annoying.
Solution: Request the "Allow Paste from Other Apps" entitlement during onboarding (the "Save Automatically" flow in Paste's screenshots). This suppresses the banner. The app must guide users through approving this in Settings.
Challenge 4: CloudKit Sync Conflicts
When a user copies something on iPhone and immediately looks on Mac, there can be a sync delay (1–3 seconds over iCloud). The app must handle:
Optimistic local writes (show immediately, sync in background)
Conflict resolution if the same item is modified on two devices simultaneously
Offline mode — clipboard keeps working locally even without internet
Challenge 5: Mac App Target — Not a Normal iOS App
The Mac app is a menu-bar utility (like Paste, Raycast, 1Password). It runs in the background at all times with no Dock icon. Building this requires:
Setting LSUIElement = YES in Info.plist to hide the Dock icon
Creating an NSStatusItem (menu bar icon) in AppKit
Running as a background agent
Handling auto-launch on Mac startup (Login Items)
If using React Native for Mac (via Mac Catalyst or react-native-macos), verify that menu-bar mode and background clipboard monitoring are achievable in that framework. If not, the Mac app must be pure native.
Challenge 6: Smart Auto-Sort Detection Accuracy
Our #1 differentiator requires detecting the type of content the user copied. The logic must be:
Fast (runs in under 50ms — user should not notice any delay)
Accurate (false positives are annoying — a hex color in code should not trigger the Colors pinboard unless the user wants it to)
Configurable (user can enable/disable each rule and add custom ones)
Use Apple's NaturalLanguage framework for general text classification and simple regex patterns for structured types (URLs, emails, color codes, JSON).
